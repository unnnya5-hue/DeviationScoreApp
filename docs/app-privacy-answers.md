# Appプライバシー回答案

最終更新日: 2026-05-18

## 前提

この回答案は、初回リリース時点の実装に合わせたものです。

- ログインなし
- 課金なし
- 外部サーバーへの診断結果送信なし
- 診断履歴は端末内保存のみ
- 位置情報、連絡先、写真、マイク、カメラは利用しない
- 広告SDKとしてGoogle AdMobを利用
- ATT許可ダイアログは未実装

App Store Connectでは、アプリ本体だけでなく、組み込んでいる第三者SDKが収集するデータも含めて回答します。

## 推奨方針

初回リリースでは、ATT許可ダイアログを入れずに提出する方針です。そのため、AdMob側でIDFAを前提にしたパーソナライズ広告やトラッキング利用を行わない前提で回答します。

AdMobの管理画面やGoogle側の同意設定でパーソナライズ広告を有効にする場合は、`NSUserTrackingUsageDescription` とATT許可ダイアログの実装を追加し、App Store Connectのトラッキング回答も見直します。

## データ収集

### 開発者サーバーへ送信するデータ

なし。

### 端末内だけに保存するデータ

App Store ConnectのAppプライバシーでは、通常「収集」には含めません。

- 診断テーマ
- 偏差値風スコア
- 結果タイトル
- 診断日時

### AdMob由来で申告するデータ

以下はGoogle Mobile Ads SDKの利用により申告対象になる可能性が高い項目です。App Store Connectの画面で該当する選択肢を選びます。

| App Store Connectの分類 | データタイプ | 主な用途 |
| --- | --- | --- |
| ID | デバイスID | 第三者広告、アナリティクス、不正防止 |
| 使用状況データ | 製品の操作 | 第三者広告、アナリティクス |
| 使用状況データ | 広告データ | 第三者広告、アナリティクス |
| 診断 | クラッシュデータ | アプリ機能、アナリティクス |
| 診断 | パフォーマンスデータ | アプリ機能、アナリティクス |
| 位置情報 | おおよその位置情報 | 第三者広告、アナリティクス |

## App Store Connectでの入力手順

1. App Store Connectで対象アプリを開く
2. `Appプライバシー` を開く
3. `データタイプを編集` を選択
4. AdMob由来のデータタイプを追加
5. 各データタイプごとに、用途を選択
6. トラッキング利用の有無を確認
7. 保存して公開準備へ進む

## トラッキング回答

初回リリースの推奨:

```text
このAppから収集したデータをトラッキングに使用しますか？
いいえ
```

ただし、これは「IDFAを取得せず、パーソナライズ広告を前提にしない」方針の場合です。パーソナライズ広告を利用する場合は `はい` になる可能性が高く、ATT対応が必要です。

## App Tracking Transparencyを入れる場合

将来パーソナライズ広告を強めたい場合は、以下を追加します。

- `Info.plist` に `NSUserTrackingUsageDescription` を追加
- 初回起動や広告表示前にATT許可ダイアログを表示
- App Store Connectでトラッキング利用を `はい` に変更
- プライバシーポリシーにトラッキング説明を明記

## 最終確認

- AdMob管理画面の広告設定とApp Store Connectの回答が矛盾していない
- プライバシーポリシーURLが公開されている
- App Store ConnectのAppプライバシー表示と実装内容が一致している
- ATT未実装のままIDFA利用前提の広告設定にしていない
